When Python cannot go on, it stops and prints a **traceback**. Read it from the bottom: the last line names the **error type** and a short message, and the lines above show the file and line number where it happened. Errors are not a sign that you are bad at programming – every programmer sees them all day. They are messages that tell you what to fix.

en: ## Errors before the program runs
A **SyntaxError** means Python could not even read the code: a missing bracket, quote or colon, or a misspelled keyword. An **IndentationError** is a kind of syntax error – the indentation of a block does not match. Nothing runs until these are fixed; the Problems panel in the editor shows them while you type.
pl: ## Błędy przed uruchomieniem programu
**SyntaxError** oznacza, że Python nie umiał nawet przeczytać kodu: brakuje nawiasu, cudzysłowu albo dwukropka, albo słowo kluczowe jest źle napisane. **IndentationError** to rodzaj błędu składni – wcięcie bloku się nie zgadza. Nic się nie wykona, dopóki ich nie poprawisz; panel Problemy w edytorze pokazuje je już podczas pisania.
de: ## Fehler, bevor das Programm läuft
Ein **SyntaxError** bedeutet, dass Python den Code nicht einmal lesen konnte: eine fehlende Klammer, ein fehlendes Anführungszeichen oder ein fehlender Doppelpunkt oder ein falsch geschriebenes Schlüsselwort. Ein **IndentationError** ist eine Art Syntaxfehler – die Einrückung eines Blocks passt nicht. Nichts läuft, bevor diese Fehler behoben sind; das Problem-Panel im Editor zeigt sie schon beim Tippen.
es: ## Errores antes de ejecutar el programa
Un **SyntaxError** significa que Python ni siquiera pudo leer el código: falta un paréntesis, una comilla o dos puntos, o una palabra clave está mal escrita. Un **IndentationError** es un tipo de error de sintaxis: la sangría de un bloque no cuadra. No se ejecuta nada hasta corregirlos; el panel Problemas del editor los muestra mientras escribes.
fr: ## Les erreurs avant l'exécution
Une **SyntaxError** signifie que Python n'a même pas pu lire le code : il manque une parenthèse, un guillemet ou deux-points, ou un mot-clé est mal écrit. Une **IndentationError** est une sorte d'erreur de syntaxe – l'indentation d'un bloc ne correspond pas. Rien ne s'exécute tant qu'elles ne sont pas corrigées ; le panneau Problèmes de l'éditeur les signale pendant que tu tapes.

en: ## Errors while the program runs
These errors appear only when Python reaches the line:

| Error | Typical cause |
|---|---|
| `NameError` | a name that was never defined, often a typo: `Age` instead of `age` |
| `TypeError` | an operation on the wrong type: `'2' + 2` |
| `ValueError` | the right type with a wrong value: `int('twelve')` |
| `IndexError` | an index past the end of a list: `[1, 2, 3][3]` |
| `KeyError` | a dictionary key that is not there |
| `AttributeError` | a method or attribute the object does not have: `'abc'.push()` |
| `ZeroDivisionError` | dividing by zero |
| `ModuleNotFoundError` | importing a module that does not exist or is not installed |
| `ImportError` | importing a name that the module does not have |

@md
en: ## How to fix an error
1. Read the last line: which error, and what does the message say?
2. Go to the line it names. The real mistake is often on that line or just above it.
3. Check the values: `print()` the variables just before the failing line, or try the expression in the Python shell.
4. Change one thing and run again.

On day 17 you will learn to *catch* errors with `try` and `except`, so that a program can deal with bad input instead of stopping.
pl: ## Jak poprawić błąd
1. Przeczytaj ostatni wiersz: jaki to błąd i co mówi komunikat?
2. Przejdź do wiersza, który wskazuje. Prawdziwa pomyłka jest często w tym wierszu albo tuż nad nim.
3. Sprawdź wartości: wypisz `print()` zmienne tuż przed wierszem z błędem albo wypróbuj wyrażenie w powłoce Pythona.
4. Zmień jedną rzecz i uruchom ponownie.

W dniu 17 nauczysz się *łapać* błędy przez `try` i `except`, żeby program umiał poradzić sobie ze złymi danymi, zamiast się zatrzymywać.
de: ## Wie du einen Fehler behebst
1. Lies die letzte Zeile: Welcher Fehler, und was sagt die Meldung?
2. Geh zu der Zeile, die genannt wird. Der eigentliche Fehler steckt oft in dieser Zeile oder direkt darüber.
3. Prüf die Werte: Gib die Variablen kurz vor der fehlerhaften Zeile mit `print()` aus oder probier den Ausdruck in der Python-Shell.
4. Ändere eine Sache und starte erneut.

An Tag 17 lernst du, Fehler mit `try` und `except` *abzufangen*, damit ein Programm mit schlechten Eingaben umgehen kann, statt stehen zu bleiben.
es: ## Cómo corregir un error
1. Lee la última línea: ¿qué error es y qué dice el mensaje?
2. Ve a la línea que indica. El fallo real suele estar en esa línea o justo encima.
3. Comprueba los valores: muestra con `print()` las variables justo antes de la línea que falla, o prueba la expresión en el intérprete de Python.
4. Cambia una sola cosa y vuelve a ejecutar.

El día 17 aprenderás a *capturar* errores con `try` y `except`, para que un programa pueda manejar datos incorrectos en lugar de detenerse.
fr: ## Comment corriger une erreur
1. Lis la dernière ligne : quelle erreur, et que dit le message ?
2. Va à la ligne indiquée. La vraie faute se trouve souvent sur cette ligne ou juste au-dessus.
3. Vérifie les valeurs : affiche avec `print()` les variables juste avant la ligne fautive, ou essaie l'expression dans l'interpréteur Python.

Le jour 17, tu apprendras à *intercepter* les erreurs avec `try` et `except`, pour qu'un programme puisse gérer de mauvaises entrées au lieu de s'arrêter.
