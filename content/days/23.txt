@md
en: ## Why a virtual environment?
Packages installed with pip normally go into one place for the whole computer. That breaks down quickly: one project needs Flask 2, another Flask 3, and an upgrade for one breaks the other. A **virtual environment** is a folder with its own copy of the Python interpreter and its own packages. Each project gets one, and what you install there stays there.

The `venv` module that creates them is part of the standard library.

Każdy projekt dostaje swoje, a to, co w nim zainstalujesz, tam zostaje.

Moduł `venv`, który je tworzy, należy do biblioteki standardowej.

en: ## Creating and using one
In your system terminal, inside the project folder:

```
python -m venv venv
```

This creates a folder `venv`. To **activate** it:

| System | Command |
|---|---|
| Windows (Command Prompt) | `venv\Scripts\activate` |
| Windows (PowerShell) | `venv\Scripts\Activate.ps1` |
| macOS, Linux | `source venv/bin/activate` |

The prompt then starts with `(venv)`, and `python` and `pip` now mean the environment's copies. Install what the project needs, save the list with `pip freeze > requirements.txt`, and leave with `deactivate`. Do not put the `venv` folder into git – add it to `.gitignore`; `requirements.txt` is enough to rebuild it.

To use a virtual environment in this app, put the path of its Python in **Settings → Python**: `venv\Scripts\python.exe` on Windows, `venv/bin/python` elsewhere.

en: ## Which Python is running?
The `sys` module tells you about the running interpreter: `sys.executable` is its path, `sys.version_info` its version, and `sys.prefix` the folder of the environment. Inside a virtual environment `sys.prefix` differs from `sys.base_prefix`, the folder of the Python it was made from.
pl: ## Który Python działa?
Moduł `sys` mówi o uruchomionym interpreterze: `sys.executable` to jego ścieżka, `sys.version_info` – wersja, a `sys.prefix` – folder środowiska. W środowisku wirtualnym `sys.prefix` różni się od `sys.base_prefix`, czyli folderu Pythona, z którego środowisko powstało.
de: ## Welches Python läuft?
Das Modul `sys` gibt Auskunft über den laufenden Interpreter: `sys.executable` ist sein Pfad, `sys.version_info` seine Version und `sys.prefix` der Ordner der Umgebung. In einer virtuellen Umgebung unterscheidet sich `sys.prefix` von `sys.base_prefix`, dem Ordner des Pythons, aus dem sie erzeugt wurde.
es: ## ¿Qué Python se está ejecutando?
El módulo `sys` informa sobre el intérprete en ejecución: `sys.executable` es su ruta, `sys.version_info` su versión y `sys.prefix` la carpeta del entorno. Dentro de un entorno virtual, `sys.prefix` es distinto de `sys.base_prefix`, la carpeta del Python a partir del cual se creó.
fr: ## Quel Python est en train de tourner ?
Le module `sys` renseigne sur l'interpréteur en cours : `sys.executable` est son chemin, `sys.version_info` sa version et `sys.prefix` le dossier de l'environnement. Dans un environnement virtuel, `sys.prefix` diffère de `sys.base_prefix`, le dossier du Python à partir duquel il a été créé.

@code
import sys
print(sys.executable)
print(sys.version_info.major, sys.version_info.minor)
print(sys.prefix)
print('In a virtual environment:', sys.prefix != sys.base_prefix)
@end

@solution
installed = {'requests': '2.32.3', 'Flask': '3.1.0', 'numpy': '2.1.3', 'Jinja2': '3.1.4'}


def make_requirements(packages):
    lines = [f'{name}=={packages[name]}\n' for name in sorted(packages, key=str.lower)]
    return ''.join(lines)


with open('requirements.txt', 'w', encoding='utf-8') as f:
    f.write(make_requirements(installed))
print(make_requirements(installed))
@end
